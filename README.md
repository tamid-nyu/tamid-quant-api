# TAMID Quant API
Shared FastAPI backend for TAMID research projects. The first strategy lives in `strategies/kalshi_tail`; shared storage, uploads, ingestion, authentication and Kalshi data belong in `shared`. Vendored strategy Python files are unchanged from `engine/SOURCE_COMMIT`; refresh with `scripts/sync_engine.sh /path/to/source`.

Run `pip install -r requirements.txt` then `uvicorn api.index:app`. Set `BLOB_READ_WRITE_TOKEN` for private Vercel Blob persistence and run `python scripts/seed.py` once. `LAB_API_TOKEN` authenticates writes. Production docs: `/docs`, schema: `/openapi.json` (also `/api/openapi.json`). No credentials belong in git.

Source results are research evidence, not a promise of returns. Frozen settings date: 2026-11-12. The source repository does not commit non-BTC observations or numbered-variant output; these must be ingested or computed, never inferred from trades.

## REST surface
Both bare paths and `/api/` prefixed paths are accepted. `/` is the resource catalog. `/strategies` is the strategy registry. The schema at `/api/openapi.json` is the complete contract; `/docs` provides an interactive Swagger client.

- `/kalshi/series`, `/events`, `/markets`, `/trades`, `/settlements`; detail endpoints for series/events/markets; market orderbooks and live/historical candlesticks. These are public market data and public settlement outcomes, not account portfolio settlements. Requests are paced at about 5.5/s per function instance, retried on transient failures, and cached in private Blob.
- `/uploads/preview` and `/uploads` accept multipart CSV/JSON, `kind`, optional `name` and JSON `mapping` from source column to canonical column. Every saved version has a UUID, SHA-256, timestamp, schema and sample. `/uploads/{id}/rows` pages data; authenticated DELETE removes a version.
- `/ingest/trigger` accepts an expiry day and market keys; `/ingest/logs` records per-market outcomes. `/ingest/cron` requires `CRON_SECRET`. The daily 23:00 UTC schedule pulls yesterday in New York, after 5pm ET in both seasons. Partitions are keyed by market/day for idempotent retries. Batch candles fall back to single-contract historical data. Missing pairs are never fabricated.
- `/strategies/kalshi-tail/markets`, `/observations`, `/trades`, `/daily`, `/summary`, `/results`, `/forward-test` and `/forward-test/results` expose research data.
- POST `/strategies/kalshi-tail/runs` executes the real engine with `markets`, `cap`, `k`, `C`, `slip`, `q_max`, `estimator`, `start`, `end`, `variant`, `upload_id`, `min_history_days`. GET list/detail, `/runs/{id}/trades`, and `/compare?left=...&right=...` expose persisted results. Dates filter the reporting window, preserving prior training history. Input order is preserved because LP tie-breaking can depend on it.

All reads, including uploaded research datasets, are public through the API. Private Blob URLs and write credentials are never returned. The public web app uses an authenticated server session for writes and injects `LAB_API_TOKEN` only on the server. Deploy API before web with `npx vercel@latest deploy --prod --yes --scope team_nrjOnKmTNVWkAdf40l6k6hkK` after merging a PR. Use `python scripts/check_live.py` for the actual production acceptance checks, including writes and cron. Keep token files outside the repository with mode 600.

## Data coverage
The source commits the complete BTC observation input and multi-market result CSVs, but omits non-BTC observation input files. Multi-market historical results are displayed exactly as committed. New backtests refuse markets below their selected history gate. Forward snapshots expose observed expiry days, eligible markets and missing frozen-market history, rather than claiming complete BTC+SPX performance. Upload historical SPX observations and activate that dataset with POST `/uploads/{id}/activate` to complete shared forward history; POST `/uploads/{id}/deactivate` removes it from shared history without deleting the version. Activation and removal recompute the forward snapshot. Custom datasets can be saved and inspected but must be mapped and validated as observations before engine use. #5 and #7 additionally require the original model probability columns.
